What it is

🎥 Virtual capture card

PSCapture registers a DirectShow device named PS5 Capture. Discord, OBS and ffmpeg see it like an Elgato — pick it and go live.

⚡ Straight from the GPU

The console payload reads the display engine's scan-out buffer directly and streams NV12 frames over your LAN. No re-encode delay, no cloud.

🖱️ One executable

PSCapture.exe carries the console payload inside itself: install the driver, push the payload, start streaming — one window, one click.

How it works

PS5 · payload
reads the DCE scan-out ring, builds NV12 frames, serves them on a TCP port, pops a toast: “PSCapture is streaming on:PORT”.
→
PC · feeder
receives frames and publishes them into a shared-memory ring.
→
PC · driver
DirectShow filter exposes the ring as a camera every app can use.

Quick start — step by step

What you need first. A jailbroken PS5 with the standard setup: a payload loader on TCP 9021 (elfldr-style), anonymous FTP on TCP 2121, and optionally the pldmgr autoloader so the payload starts on every boot. PC and console on the same LAN. Download PSCapture.exe from the Releases page — it's one single file: the console payload and the Windows driver are inside it.
  1. Jailbreak the console
    Any kernel-capable jailbreak that gives you the payload loader (:9021), anonymous FTP (:2121) and — optionally — the pldmgr autoloader.
  2. Double-click PSCapture.exe
    Windows asks “Do you want to allow this app to make changes?” → Yes. The app elevates itself; admin is needed once, to register the virtual camera for every program on the machine.
  3. Check the IP
    If your PS5 is not at 192.168.0.36, type its address in the PS5 IP field and press Apply.
  4. Watch it work — press nothing
    The app does everything alone, and narrates it in the dark log pane (see the table below). On the console you will also see the system notification “PSCapture is streaming on:PORT”.
  5. Use it in any app
    Discord (call): Settings → Voice & Video → Camera → PS5 Capture (720p — Discord asks every camera for 720p, capture cards included). OBS: add a Video Capture Device → full 1920x1080. ffmpeg: -f dshow -i video="PS5 Capture".

Daily use & tuning

  • Open PSCapture.exe (UAC → Yes). If the payload is already on the console (autoloader), the stream starts by itself; otherwise press Deploy payload once.
  • Stop / closing the app stops the stream — the camera freezes on the last frame and consumers keep the device listed.
  • gain — chroma strength. Leave it at 1.0 (raw) unless colors look off.
  • shift px — horizontal alignment. Even numbers only (an odd value inverts the colors). Applies live, saved in pscapture.ini next to the exe.

Build from source

Sources only — the repo contains no binaries. Two halves, two toolchains. The full walk-through (toolchain install, verification, gotchas) is in docs/BUILD.md.

1 · Console payload → pscapture.elf

# needs Docker + the PS5 payload SDK image (prospero-clang; here tagged ps5sdk:18)
docker run --rm -v "<repo>/payload:/payload" -w /payload ps5sdk:18 make

2 · PC side → pscapture.exe + pscapture.dll

Needs MinGW-w64 (gcc + windres). The order is mandatory: the .res embeds the driver and the payload as they are on disk.

# from the repo root
cp payload/pscapture.elf pc/        # it gets embedded as-is
cd pc

# 1) the capture-card driver (DirectShow source filter)
gcc -O2 -shared -static -static-libgcc -o pscapture.dll ps5cam.c \
    -lole32 -loleaut32 -luser32 -ladvapi32 -lws2_32

# 2) bundle icon + payload + driver into the resource object
windres pscapture.rc -O coff -o pscapture.res

# 3) the single-file app
gcc -O2 -mwindows -o pscapture.exe pscapture.c pscapture.res \
    -lws2_32 -lshell32 -ladvapi32 -luxtheme
Why the order? (and the two classic build mistakes)

windres embeds files as they are on disk: if the DLL or the payload is rebuilt after step 2, the exe still carries the old ones. Rebuild = DLL → windres → exe, every time.
-static -static-libgcc on the DLL is mandatory: without it Windows can fail to load the driver with the cryptic “the specified module could not be found” (missing mingw runtime).

FAQ

Does it work on firmware versions older than 13.60?

The PC side works on every firmware: the app and the driver only speak TCP/FTP and shared memory. The console payload is the version-specific part — it was built and tuned on 13.60, using display-engine anchors found on that firmware. On other firmwares it may need a small porting pass (the fix is finding the same anchors on that system). If you have another firmware, open an issue with your version and we can add a profile.

Why is the call camera 720p and not 1080p?

That cap is Discord's voice engine, not PSCapture: it requests 1280x720 from every camera. For full-quality capture use OBS (where PS5 Capture runs at 1920x1080) or Discord's screen-share, which goes up to 1080p60 with Nitro.

Is a capture card or Remote Play needed?

No. PSCapture never touches Remote Play: the payload reads the display engine on the console itself and streams raw frames over your LAN.

How do I uninstall it?

Close the app, then rundll32 "%ProgramFiles%\PSCapture\pscapture.dll",DllUnregisterServer, delete C:\Program Files\PSCapture, and optionally delete /data/pldmgr/payloads/pscapture/ on the console so the autoloader stops starting the payload.
